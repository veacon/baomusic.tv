# 全屏歌词特效：主流方案调研 + 两套全新方案设计

> 适用项目：宝听（baoge-tv / walkman-tv），Android TV + Jetpack Compose
> 现有全屏歌词档位：`FullscreenLyricFx = NONE / LIGHT / STARSEA`（关闭 / 光感 / 星海）
> 本文中「方案 A / 方案 B」拟新增为 `INK_SCROLL / TRACK_BED`，与既有档位并列。

---

# 第一部分　调研要点汇总

## 1.1 主流形态与技术内核

| 形态 | 代表项目 | 核心技术要点 | 视觉 / 交互特征 |
|---|---|---|---|
| **逐字扫光（karaoke gradient）** | AMLL（applemusic-like-lyrics）、MD3Music、Lyricify、BetterLyrics | 音节级时间戳（TTML / QRC / YRC / KRC / LYS）；**文字恒白，只用 alpha / 遮罩（CSS `mask-image`、Compose `SrcAtop` + 渐变）区分已唱 / 未唱**；正在唱的字按指数衰减过渡；每帧 tick 推进，行位置用**弹簧物理** | 逐字点亮、行滑动有惯性、拖腔时字尾拖光 |
| **波形 / 频谱律动** | Folia、RealTimeSpectrogramFFT | Web Audio `AnalyserNode` FFT 或 `AudioRecord` → 频点能量 → 映射到条高 / 着色 | 背景随鼓点起伏，视觉冲击强但不承载文字 |
| **3D / 空间滚动** | Folia「回环」、BetterLyrics「spatial perspective」 | React Three Fiber 3D 场景 / 伪 3D 环绕排布；远处歌词按景深淡出与缩放 | 歌词在纵深里穿行，鼠标可拖拽视角 |
| **粒子 / 霓虹辉光** | Folia「流光 / 绘光 / 时计」、WebGL 着色器系 | WebGL / Pixi.js 着色器、WebGL2 画齿轮与粒子、bloom 后处理 | 粒子流光、辉光溢出，强依赖 GPU |
| **歌词挂载（悬浮 / 桌面 / 状态栏 / 壁纸）** | Lyricon（词幕）、APlayer、AirLyrics、BetterLyrics 壁纸模式 | 悬浮窗 overlay（TYPE_APPLICATION_OVERLAY）/ 桌面小组件 / SystemUI Hook / 壁纸模式；靠 MediaSession 读取正在播放的媒体 | 脱离播放器本体，桌面 / 其它 App 上方常驻 |
| **长音强调 / HDR 提亮** | MD3Music `EmphasizeEffect`、Lyricon「拉长音发光」 | 音节时长 ≥ 阈值（1000ms）触发逐字放大 + 上浮 + 正弦起伏；HDR 设备上突破 SDR 亮度 | 拖腔时字「活」起来，句尾记忆点强 |
| **主题化 / AI 配色** | Folia AI 主题、AMLL mesh gradient | 封面取色 → 调色板 → WebGL 双三次 Hermite 网格渐变 | 背景与歌曲同色系，视觉统一 |

## 1.2 跨方案的技术共识（可直接抄的六条）

1. **时间基准必须是媒体时钟**，不是每秒一次的 tick。
   AMLL 用 `requestAnimationFrame` + 音频时间并做自适应校准，误差压到 50ms 内；
   Android 侧对应 `ExoPlayer.currentPosition`（内部按 `SystemClock.elapsedRealtime` 外推）。
   —— 本项目已在 `PlaybackController.livePositionMs()` 落地。
2. **时间轴数据层级**：行级 LRC → 音节级（QRC/YRC/KRC/TTML/LYS）→ 对唱标记 → 翻译 / 罗马音。
   翻译对齐用**最近邻匹配 + 500ms 容差**（MD3Music）吸收 LRC 与 KRC 的时间戳精度差。
   没有音节级数据，就只能线性插值 —— 这是「机械感」的物理上限，不是调参能解决的。
3. **渲染分层**（避免每帧全树重组）：背景层（低频）→ 行 / 块级（换行时）→ 高亮层（每帧）。
4. **度量缓存**：`TextMeasurer` 带 LRU 缓存，且**颜色 / 阴影 / brush 属于「绘制期参数」，不参与布局缓存键**
   → 动画化颜色不触发重新排版。MD3Music 把「每帧每字测量」改成「切行 / 改字号时测一次」，
   10 字行从每秒 600 次布局降到约 0。
5. **实时绘制的天花板**：Compose Canvas 在 **UI 线程**绘制，递归 / 高频更新会与组合抢线程；
   真要 60fps 的音频可视化，Android 上的正解是 **SurfaceView 独立渲染线程**（或 AGSL `RuntimeShader`，API 33+）。
6. **优雅降级**：解析失败降级纯文本；Android 8 无 RenderEffect / AGSL 时用 Canvas 近似；
   低内存设备（1.5GB）关掉次级特效；HDR / 广色域做可选开关。

## 1.3 交互外壳（常被忽略但体验分很高）

AirLyrics：点击穿透、拖动锁定、暂停自动隐藏、毫秒级偏移校准、手动导入优先于联网搜索。
Lyricon：对唱模式（双歌手分栏）、超小米「灵动岛」联动、拉长音呼吸发光。
APlayer：悬浮窗 + 桌面小组件双形态，普通 / 暗色 / 纯黑 AMOLED 三套主题。
**启示**：全屏歌词的「档位」只是外形，真正的差异在**交互契约**（跟随 / 可翻阅 / 可演奏 / 可拖拽）。

# 第二部分　方案 A《墨卷 Ink Scroll》

> 一句话：**把「逐字」从「颜色扫描」改成「书写落墨」，把排版从「横向行」改成「竖排手卷」，
> 把交互从「只能跟随播放」扩展为「可停下细读」。**

## 2.1 歌词排版结构

| 项 | 规格 |
|---|---|
| 走向 | **竖排，自右向左推进**（传统手卷 / 册页顺序） |
| 列的构成 | 一句 = 一列；列内自上而下逐字排布，标点悬挂右侧 |
| 行数 | 每列 1 句；句长超出列高时按语义断列（`，`、`、`、`。` 前优先），最多 3 列，续列字号 ×0.92、段首缩进 1 字 |
| 区域分配 | **右侧 1/3 = 当前列**（大字号 1.0×）；**中间 1/3 = 已写卷**（0.82×，墨色随时间变淡）；**左侧 1/3 = 留白**（未来句不显示） |
| 对齐方式 | 列内**字顶对齐**；列间基线垂直；翻译以「夹注」小字排在原文列**右侧半字宽**处（不是下一行） |
| 与背景关系 | 背景 = **宣纸底纹**（细噪点 + 极淡横向纤维，512×512 噪声贴图平铺），**不使用封面实拍图**；封面仅以 12% 透明度的**朱砂方章**落在左下角（像落款） |
| 与其它层的关系 | 歌词层是唯一前景层，纸面之上不叠任何粒子 / 光效（保证「读得清」是这一档的硬指标） |

## 2.2 动画时序与触发规则

| 事件 | 动效 | 时长 / 曲线 |
|---|---|---|
| **落笔**（字被唱到） | alpha 0→1；scale 0.82→1.0（以字心为原点）；字心扩散一圈**墨晕**（半径 0→1.4 字高，alpha 0.5→0） | 字 180ms；墨晕 300ms；`FastOutSlowInEasing` |
| 连笔 | 同一列内允许相邻 2 字动画重叠（像行草连写） | 重叠窗口 60ms |
| **沉纸**（一句唱完） | 整列向左沉入纸面：translationX −12px、alpha → 0.18；纸面留一道极淡水痕 | 延迟 400ms 后启动，600ms 缓入 |
| **翻阅**（手动） | 遥控器 ↑ / ↓ 翻到下一句 / 上一句；翻阅时整列**直接以「已写满」状态呈现**（不做逐字回放） | 260ms |
| **阅读态进出** | 进入阅读态时右下角浮出「阅读中 · 按 OK 跟随」胶囊，5s 无操作或按 OK 自动回到跟随态 | 胶囊 200ms 淡入 |
| **跟随态的按键** | ↑ / ↓ = 无操作（避免误触），← / → = 无操作，OK = 进入阅读态 | — |
| **拖腔**（音节 ≥ 1200ms） | 该字在保持期内做 1.2Hz、±4% 呼吸缩放，墨色 alpha 0.85→1.0；句尾字额外加一道向下墨拖尾（拉长 1.15× 后回落） | 拖尾 120ms |
| **Seek / 切歌** | 立即重算：已过时间的字**一次性落墨**（不做补间），沉纸状态同步跳变 | 0ms（硬切） |
| **暂停** | 所有动画冻结在当前帧（纸纹漂移也停） | — |

## 2.3 设计参数

**配色**

| | 宣纸模式（浅） | 夜墨模式（深） |
|---|---|---|
| 纸底 | `#F3EADA` | `#121110` |
| 主墨（当前字） | `#1B1A17` | `#EDE7DA` |
| 淡墨（历史） | `#1B1A17` @ 35% | `#EDE7DA` @ 30% |
| 朱砂（印章 / 点睛） | `#B23A2E` | `#E0564B` |
| 纸纹 | `#1B1A17` @ 4% 噪点 | `#EDE7DA` @ 3% 噪点 |

**字体**：衬线（思源宋体 / 系统 serif）为主，字重 Medium；当前列字号 = 基准 1.0×，历史列 0.82×；
字距 +0.08em；列距 = 1.9 × 字高；时间码 / 歌名用无衬线小字（12sp @ 40% 墨色）压在左下印章旁。

**动效节奏**：落笔 180 / 墨晕 300 / 沉纸 600 / 翻页 260；**全局「慢—快—慢」的呼吸节奏，全程不做弹跳**（这是与「星海」「光感」拉开气质差异的关键）。

**氛围细节**：纸面纹理以 60s 为周期做 2% 横向漂移；播放中纸面比暂停时**亮 4%**（像纸被照到）。

## 2.4 屏幕适配与深浅色

- **以高度为基准**（竖排按高度排）：当前列字号 = 屏高 × 0.052（1080p ≈ 56px）；下限 34px（720p）。
- 列数按宽度自适应：16:9 → 5 列；4:3 → 4 列；21:9 → 6 列；超宽屏再加密到 7 列。
- 深浅色：跟随系统 / 设置项；切换用 400ms 交叉淡入，**切换瞬间不重排**（排版与字号无关色板）。
- 低配降级（`isLowRamDevice` 或可用内存 < 1.5GB）：关闭墨晕扩散、呼吸缩放、纸纹漂移，只保留 alpha 渐显。

## 2.5 实现要点

- **模块划分**
  - `InkScrollLayout`：竖排流式布局 + 语义断列（输入：句文本，输出：列矩形 + 每字坐标）
  - `InkGlyphRenderer`：Canvas 逐字绘制 + 墨晕扩散 + 拖尾
  - `InkPaperBackground`：纸纹平铺 + 朱砂印章 + 暗角
  - `InkScrollController`：跟随态 / 阅读态状态机、翻页、按键契约
  - `InkPalette`：浅 / 深两套色板（与 `FullscreenLyricFx` 解耦，但由它触发）
- **数据流**：`MediaClock` →（每帧）`positionMs` → `InkTimeline`（算每字状态：未写 / 正在写 / 已写）→ **绘制阶段**读取，不进 composition。
- **性能**：只绘制当前列 ±2 列；历史列走「整列批量淡墨」简化路径（一次 drawText，不逐字）；纸纹用单张贴图平铺，不做程序化噪声。

# 第三部分　方案 B《声轨 Track Bed》

> 一句话：**把歌词当成一段「时间工程」来排 —— 一句 = 一个音轨块，块长 = 时值，块内按音节切成格子；
> 屏幕底部一条贯穿的时间轴与游标就是主控件。交互是「工程师」式的：scrub、看刻度、切视图。**

## 3.1 歌词排版结构

| 项 | 规格 |
|---|---|
| 整体 | 三层竖向分区：顶部 12% 歌名 / 歌手（单行极简）· 中部 70% **音轨区** · 底部 18% **时间轴标尺** |
| 轨道块 | **一句 = 一个块**；块宽 = 该句时值 × 每秒像素（pps，1080p ≈ 115px/s → 4s 句 ≈ 460px）；块高固定 |
| 对唱 | 有对唱标记时**分双轨**：主唱上轨、伴唱下轨，各自独立的时间轴块 |
| 块内文字 | 小号（基准 16–18sp），**左对齐**，不换行，超宽显示省略号 |
| 行数 | 横向无限延伸（时间轴本质），垂直最多 2 轨 |
| 对齐方式 | 块按**时间左对齐**（左边缘 = 歌词起始时刻 × pps）；块内文字左对齐 + 2px 内边距 |
| 与背景关系 | 深色工程底 + 细网格（每 2s 一细竖线，每 4 小节一粗线，透明度 6%）+ 顶底暗角；**不叠封面实拍图**，只在当前块上用封面色做 6% 填充作为定位锚 |
| 已唱 / 未唱 | 已唱块保留在轨道上（亮度 45%）；未唱块只显示 1px 虚线占位框 —— **看得见的未来** |

## 3.2 动画时序与触发规则

| 事件 | 动效 | 时长 / 曲线 |
|---|---|---|
| **逐格点亮** | 音节时间戳到达 → 该小格自左向右「扫描填充」（像音频波形的填充动画），填充色 = 封面色提亮 40% | 120ms，`LinearEasing` |
| 点亮闪光 | 每格点亮叠加一帧白闪（alpha 0.35→0） | 80ms |
| **块激活** | 当前句所在块：描边 1px→2px + 8% 封面色填充 | 220ms，`FastOutSlowInEasing` |
| **游标** | 连续跟随媒体时钟（60fps），2px 竖线 + 顶部小三角；整秒处刻度「咔哒」亮度 +12% | 连续 / 90ms 衰减 |
| **拖腔** | 该音节格子做 0.6Hz ±8% 亮度呼吸；块顶出现「延音条」（宽度随剩余时长收缩） | 实时 |
| **Scrub** | ← / → = ±2s；**按住 0.5s 后加速到 ±8s/次**；松开立即 seek，轨道整体重建（已唱区间一次填满） | 按键 0ms，seek 即时 |
| **视图切换** | ↑ / 下 = 「音轨视图 ⇄ 纯文本阅读视图」；纯文本视图退回标准逐字行（复用现有标准页渲染） | 300ms 交叉淡入 |
| **展开** | OK = 把当前块展开成大字浮层（完整文本 + 翻译），再按 OK 收起 | 260ms |
| **跳段** | 长按 ↑（>800ms）= 跳到下一段主歌（优先用歌曲结构标签，无标签则退化为下一句） | — |
| **暂停** | 游标停住，整体亮度降到 60%，延音条冻结 | — |

## 3.3 设计参数

**配色**

| | 工程纸（浅） | 机房（深，默认） |
|---|---|---|
| 底 | `#F6F7F9` | `#0E1013` |
| 网格 | `#101418` @ 8% | `#FFFFFF` @ 6% |
| 未唱占位 | `#101418` @ 22%（1px 虚线） | `#FFFFFF` @ 18% |
| 已唱块 | `#101418` @ 45% | `#FFFFFF` @ 45% |
| 当前块描边 / 填充 | 封面色 S0.55 V0.85 | 封面色 S0.60 V0.95 |
| 文字 | `#12151A` | `#F2F4F7` |
| 游标 | `#12151A` | `#FFFFFF` |

**字体**：歌词用无衬线（系统默认）；**刻度与时间码用等宽**（JetBrains Mono / 系统 monospace，11sp），
体现「工程仪表」气质，与方案 A 的宋体形成硬对比。

**动效节奏**：格填充 120 / 块激活 220 / 游标连续 / 展开 260；**偏「机械、克制」，不用辉光、不用弹跳、不用粒子**。

**尺寸**：pps = 屏宽 × 0.06（1080p → 115px/s）；轨道区高度 = 屏高 × 0.70；底部标尺区 = 屏高 × 0.18。

## 3.4 屏幕适配与深浅色

- pps 与块高按比例；4:3 → pps × 0.8（保证 4s 句仍能完整显示）；21:9 → **不改 pps，改可视时间窗**（±6s → ±9s）。
- 触屏：点块直接 seek（TV 端以遥控器 scrub 为主）。
- 深浅色：默认跟随系统；浅色 =「工程纸」，深色 =「机房」；**几何逻辑完全一致，只换调色板对象**。

## 3.5 实现要点

- **模块划分**
  - `TrackTimeline`：歌词 → 时间轴坐标 + **虚拟化窗口**（可视时间窗 ± 前后各 2 块）
  - `TrackCanvas`：单 Canvas 绘制所有块 / 网格 / 文字 / 描边（**不为每块建 Composable**）
  - `RulerCursor`：标尺刻度 + 游标 + 咔哒反馈
  - `TrackController`：scrub 加速状态机、视图切换、展开浮层、跳段
  - `SpectrumMini`（可选）：底部 8px 高的迷你频谱，60fps，**用 SurfaceView 独立线程**以免拖累 Compose
- **数据流**：`MediaClock` → `TimelineLayout`（滚动窗口内块列表，低频）→ 绘制层每帧只更新游标与正在点亮的格子。
- **性能**：整轨一块 Canvas；文字用 `drawText` + `TextMeasurer` 缓存（仅在文本/字号变化时重测）；
  只有被选中的块用真正的 `Text` 组件画展开气泡。

# 第四部分　两套方案的差异化与共同工程底座

## 4.1 与主流形态的差异化对照

| 维度 | 主流做法 | 方案 A 墨卷 | 方案 B 声轨 |
|---|---|---|---|
| 逐字表达 | 颜色 / 遮罩扫描 | **书写动作**（alpha+scale+墨晕落笔） | **格子填充**（时间工程单元） |
| 排版方向 | 横排 | **竖排手卷** | 横向时间轴（时间即空间） |
| 时间呈现 | 隐含（跟随播放） | 隐含 + 可翻阅 | **显式**：块长=时值，刻度可见 |
| 交互契约 | 只能跟随 | **可停下细读**（阅读态） | **可 scrub / 切视图 / 展开**（工具态） |
| 背景关系 | 封面实拍 + 渐变 / 网格 | **纸纹，无实拍图**，封面只做落款印章 | **工程网格**，封面只做当前块 6% 填充 |
| 气质 | 音乐 / 派对 / 科幻 | **文学、手作、克制** | **工程、精确、冷静** |
| 是否复用既有特效 | — | 与「光感」「星海」完全不同轴 | 与「光感」「星海」完全不同轴 |

## 4.2 共同工程底座（两套方案共用，一次做完两套受益）

### (1) 逐字时间戳对齐

- **数据模型扩展**：新增 `LyricWord(text, startMs, endMs)`，`LyricLine` 增挂 `words: List<LyricWord>`。
- **解析器**：KRC（酷狗 `[offset,dur]word(0,dur)`）、QRC（QQ `[start,dur]word`）、YRC（网易行内 `word(start,dur)`）、TTML、LYS；
  统一归一化为毫秒。已有 LRC 解析器保留为 fallback。
- **LRC 降级也要「不均匀」**：无音节数据时按字数均分时间，但给标点加权重
  （`，`、`、` ×1.6，`。`、`！`、`？` ×2.2，空格 ×0.6），
  于是「唱到逗号会有短暂停一下」的呼吸感自然出现，不再是匀速扫过。
- **真值只有媒体时钟**：`PlaybackController.livePositionMs()`；每帧读一次，不做自累计。
- **偏移校准**：设置里提供 ±500ms 微调，按「曲目 id + 歌词 hash」持久化；seek 后立即重算。

### (2) 分层数据流（防重组的核心纪律）

```
Layer 0  背景层    封面取色 / 纸纹 / 网格      变更频率：切歌      → remember + LaunchedEffect(picUrl)
Layer 1  行块层    activeIndex / 列或块布局   变更频率：换行      → composition
Layer 2  字格层    逐字进度 / 亮度 / 游标     变更频率：每帧      → 只在 draw 阶段读 state
```

铁律：**逐帧量一律不进 composition**。每帧只做一次 `positionMs` 读取 → 写入一个
`mutableFloatStateOf` → 在 `graphicsLayer` / `drawWithContent` 内读取。
一旦把 `progress` 传进 Composable 参数，整棵歌词树会每帧重组，电视上必掉帧
（本项目 v1.2 已经踩过一次：`animateFloatAsState` 读值进 composition 导致换行动画期间逐帧重组 13 行 Text）。

### (3) 大量歌词的渲染与内存控制

| 手段 | 做法 |
|---|---|
| 虚拟化窗口 | A：只渲染当前列 ±2 列；B：只渲染可视时间窗（±6s / ±9s）+ 前后各 2 块。200 行的歌，实际每帧只处理 ≤ 9 个单元 |
| 度量缓存 | `rememberTextMeasurer(cacheSize = 32)`；字宽 / 行高只在「文本、字号、约束」变化时重测；**颜色、阴影、缩放是绘制期参数，不进布局缓存键**，动画化颜色不触发重排 |
| 少 Composable、多 Canvas | 轨道这类「同构元素」用单 Canvas 批量 `drawText/drawRect`；不要一行一个 `Text`（200 行 = 200 个布局节点） |
| 内存上限 | 纸纹 / 噪点用单张 512×512 ARGB_8888（≈1MB）平铺，不做程序化噪声；网格用 Path 不做位图；歌词全文常驻 < 200KB/首，缓存上限 20 首 + LRU |
| 帧预算 | 每帧绘制 ≤ 2ms；超预算自动降级（先关描边 / 阴影，再关次级动画，最后降到 30fps） |
| 低配降级 | `ActivityManager.isLowRamDevice` 或可用内存 < 1.5GB：关墨晕、关迷你频谱、关纸纹漂移 |
| 帧率控制 | 统一用 `withFrameNanos` 驱动，可按性能档位跳帧（30fps），避免「掉到 24fps 后更卡」的负反馈 |

### (4) 与现有工程的接入

- `FullscreenLyricFx` 扩展两个枚举值：`INK_SCROLL`、`TRACK_BED`；沿用现有进入 / 退出动画与遥控器按键分配。
- 旧存档兼容：`SettingsStore` 里自定义序列化器把未知值映射到 `NONE`（照搬 CINEMA→LIGHT 的既有做法）。
- 设置页：两档各自暴露 3–4 个参数（字号 / 密度 / 强度），默认值即设计文档中的推荐值。
- 与 Apple Music（RNPN）页的关系：RNPN 是**播放页内的右栏歌词**；本文件两套是**全屏沉浸模式**，
  进入 / 退出走现有全屏歌词通道，互不干扰。

# 第五部分　落地顺序建议

1. **先做底座**（一次投入两套共用）：`LyricWord` 模型 + KRC/QRC/YRC 解析器 + 媒体时钟对齐 + LRC 标点权重降级。
2. **再做方案 A《墨卷》**：竖排布局 + 断列是纯排版逻辑，Canvas 逐字绘制可控，
   **不依赖音节级数据也能出效果**（LRC 降级已够），适合先出可用版本。
3. **再做方案 B《声轨》**：需要音节级数据才有意义（格子 = 音节），
   且轨道的虚拟化窗口、scrub 加速状态机是主要工作量。
4. 两者共用 `FullscreenLyricFx` 入口、帧率控制、低配降级与帧预算监控。

## 风险与取舍

| 风险 | 影响 | 缓解 |
|---|---|---|
| 竖排在电视上阅读习惯差异大 | 一部分用户不适应 | 作为**可选档位**，与横排方案并存；默认可设为「标准 / 光感」，用户主动切换 |
| 音节级歌词源覆盖度不足 | 方案 B 的格子会退化为「按标点权重估算」 | 保留 LRC 降级路径，格子数量按估算切分，观感仍成立（只是不精确） |
| 逐帧 Canvas 在低端 SoC 上吃紧 | 掉帧 | 帧预算监控 + 自动降级 + 可选 SurfaceView 独立渲染线程 |
| 语义断列（标点/停顿）判定不准 | 断列位置不自然 | 优先按标点，其次按字数上限；断列结果缓存（按文本 hash） |

**与设计稿的两处偏差**（遥控器按键资源有限，实现时做了收敛）：

1. 设计稿里「OK = 展开大字 / 切视图」，实现改为：**OK 一律只做「唤回底部控制栏」**（不区分长短按）。
   声轨不再做「展开浮层」，也不再做纯文本视图切换 —— 遥控器按键资源有限，OK 只保留一个语义最不容易误操作。
2. 设计稿里「声轨 ↑ / ↓ 切换视图」改为 **↑ / ↓ = 上/下一句**（跳转到该句起点），上下键跳句更符合电视操作直觉；
   ← / → 拖动时间轴在实测中被移除（与底部进度条重复且易误触），声轨方向键只保留 ↑ / ↓。

**性能要点（已落地）**：

- 逐帧量全部在绘制阶段计算（`withFrameNanos` 心跳只用于触发重绘），不进 composition；
- 墨卷的落笔 / 墨晕 / 沉纸 / 呼吸**全部由播放位置推导**（age = now − 该字起始时间），不需要动画状态；
- 每句的音节时间片按句缓存（切歌才重算），列切分按标点断列；
- 声轨整条轨道用**单个 Canvas** 绘制，块文字用 `TextMeasurer`（cacheSize 256）缓存排版结果；
- 纸纹噪点固定种子生成一次（220 个点），不做程序化噪声；
- `TextMeasurer` 只测量字符级文本，颜色 / 缩放属绘制期参数，不触发布局重算。
